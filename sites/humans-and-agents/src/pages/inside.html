Inside a company

Inside a company

Inside one company, the hard questions mostly have answers. Everyone signs in through the same identity provider, works under the same policies, and answers to the same legal entity. That's why most agent work starts here.

Evidence current to 18 October 2026

People directing agents

The most common setup is a person and their copilot. The person asks for a draft, an analysis, or a change to a system, and the agent does the work inside the company's own tools.

Most large companies are somewhere in this stage, and few are past it. McKinsey found 62% of large firms at least experimenting with agents in mid-2025, but only 23% scaling them anywhere, and no more than 10% in any single function. Capgemini, with a stricter definition, put full-scale deployment at 2%.

Most of what agents do here is drafting. They write the email, the summary, the ticket update, and a person reads it and sends it. The person stays in the loop by default, which is a big part of why this pattern spread fastest.

Agents reaching company systems

An agent is only useful if it can reach the systems where the work lives: the CRM, the ticketing tool, the code repository, the data warehouse. MCP became the standard way to connect them. Anthropic reported 97M monthly SDK downloads in December 2025, and the official registry listed 18,849 servers by July 2026, half of them reachable over the network rather than installed locally.

The company decides which agent reaches which system through the same directory it uses for employees. MCP's Enterprise-Managed Authorization, stable since June 2026, lets the company's identity provider grant an agent access to an app on a person's behalf, with no separate sign-in or API key. Asana, Atlassian, Figma, Linear, and Supabase support it, and Okta is the identity provider named so far.

The directories themselves now treat agents as staff. Okta's Agent SSO went generally available in August 2026, and Microsoft's Agent 365 registry in May. Agents get identities, owners, and access reviews, the way employees do.

Agents working with agents

The next step is agents handing work to each other. A research agent passes findings to a writing agent, which passes a draft to a review agent. KPMG found about a quarter of large US firms running multi-agent systems in the third quarter of 2026. Microsoft built A2A into Azure AI Foundry and Copilot Studio, and AWS built it into Bedrock AgentCore, according to the Linux Foundation.

These systems fail in predictable ways. A study of multi-agent failures sorted them into bad specifications, agents that misunderstand each other, and missing checks on the final result. Gartner expects more than 40% of agentic projects to be canceled by the end of 2027, citing cost, unclear value, and weak risk controls. Still, everything here happens inside one company, so a failure is that company's own problem to fix.

Who approves

A person still approves anything that leaves the building or moves money. Only 20% of respondents in a PwC survey trust agents to make financial transactions on their own. Capgemini found trust in fully autonomous agents fell from 43% to 27% in a year. In KPMG's survey of asset managers and private-equity firms, the share that bars agents from sensitive data without human oversight jumped from 36% to 75% in a single quarter.

The weak point of approval is the person doing it. Anthropic reports that users approve 93% of manual permission prompts in Claude Code. An approval step only protects the company if it shows what the agent is about to do in a form the agent can't dress up.

What's missing inside

The biggest gap inside a company is the agents it can't see. Workers at more than 90% of companies use personal AI tools for work, while only 40% of companies pay for an official subscription, according to MIT's NANDA project. Every control above assumes the agent comes through the company directory. A personal ChatGPT or Claude account doesn't.

The second gap is that outsiders' content still gets in. The best-known agent vulnerabilities of 2025 followed one path: an agent inside the company read something from outside. EchoLeak used one external email to pull privileged data out of Microsoft 365 Copilot. ForcedLeak planted its payload in a Salesforce web-to-lead form. A public GitHub issue led an agent to publish private repository data.

Meta's "Agents Rule of Two" turns this into a deployment rule, as Simon Willison summarizes it. In one session, an agent may read untrusted input, touch sensitive data, or communicate externally, but not all three without supervision. Inside the company, that rule is enough. The trouble starts when the work itself has to cross the company line.
